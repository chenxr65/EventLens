# EventLens — 投资事件证据追踪台

> 面向投资研究场景的 AI 事件追踪产品：把散落在公告、新闻、市场传闻中的碎片信息，组织成**以事件为中心、以证据为基础**的持续演化主线——看清最初来源、事实变化、证据冲突、当前状态与关注标的的关系。
>
> **交付形态**：本地可运行的完整工程（Windows 一键启动，断网可用）。启动后浏览器访问 `http://127.0.0.1:8000`。

---

## 1. 项目简介

同一投资事件会以公告、新闻、研报观点、市场传闻等形式持续演化，信息碎片化、互相矛盾且真假难辨。EventLens 的核心原则是：

- **以事件为中心，而不是以新闻为中心**——多条材料合并为同一个事件，并保留版本演化历史；
- **以证据为基础，而不是以模型摘要为结论**——AI 的每条判断都挂接原文引用，经引用回溯校验后方可成立。

本工程内置一次真实数据采集与分析的完整快照（数据采集时段 2026-09-10 ~ 2026-10-13，全部为真实数据，`data_origin=real`），并支持联网增量更新（新材料导入、热点追踪）。

**当前监控数据规模**（均可在产品内实时核对）：

| 指标 | 数值 |
| --- | --- |
| 追踪事件 | 8 个（4 个预置 + 4 个经"热点追踪"实时生成；其中 7 个追踪中、1 个已停止追踪） |
| 有效材料 / 无关材料 | 103 条 / 72 条（AI 语义过滤） |
| 主张 / 证据 | 50 条 / 87 条 |
| 证据引用回溯校验通过率 | **100%（87/87）** |
| 事件版本 | 21 个（含状态变更 13 次通知） |

## 2. 目标用户与核心问题

| 用户 | 痛点 | 产品价值 |
| --- | --- | --- |
| 个人投资研究者 | 消息多、真假难辨、重复阅读 | 一眼看清事件状态、证据链与关键变化 |
| 机构研究员/投研助理 | 跟踪事件费时、结论难回溯 | 事件版本统一管理、冲突证据并列、可追溯到原文 |

核心问题：**"这件事最初是谁说的？后来变了什么？哪些说法互相矛盾？现在到底什么情况？跟我关注的股票什么关系？"**

## 3. 核心功能

1. **事件识别、合并与版本演化**——多源材料归并为同一事件；版本链（V1→Vn）记录每次实质变化的前后状态与原因；重复材料（同一公告多片段、转载）自动识别，不产生虚增版本。
2. **事实 / 观点 / 推测 / 传闻区分**——每条主张标注类型与证据状态（有证据支持 / 存在反证 / 证据不足……）；来源角色（官方声明 / 第三方数据 / 媒体评论 / 转载 / 网络传闻）分档计权。
3. **证据权重可解释**——W = 0.30×来源权威 + 0.20×直接程度 + 0.20×独立性 + 0.15×时效性 + 0.15×完整性（启发式评分，非真实性概率；每项评分在产品内可展开查看）。
4. **四类时间分离处理**——事件发生时间（未知则保持未知，不用披露时间代替）、披露时间、抓取时间、更新时间。
5. **状态变化与通知**——更新、否认、更正、过期触发结论重估与通知；同一实质变化不重复通知。
6. **热点榜与一键追踪**——iFinD 热点事件资讯定时刷新（30 分钟），一键将热点追踪为新事件（自动采集材料→AI 分析→生成事件）。
7. **新材料收件箱**——手动导入新材料，自动完成"去重识别 → 事件归并 → 证据更新"。
8. **关注标的与影响验证**——事件关联标的（主体/关联方/检测机构等）；行情影响验证：事件窗口收益、相对沪深300超额、K线版本标注。
9. **全链路可追溯**——从任一条结论 → 证据 → 原文引用在材料中高亮定位；**引用必须逐字存在于原文，否则该证据不得作为确认依据**。
10. **取消/恢复追踪**——事件可停止追踪（历史完整保留、统计与通知联动），随时恢复。

## 4. 技术架构

```
┌────────────────────────────────────────────────────────────┐
│  前端  Vue 3 + Element Plus + ECharts（构建为静态产物）        │
│  页面：事件总览 / 事件详情 / 热点榜 / 通知中心 / 关注标的        │
├────────────────────────────────────────────────────────────┤
│  后端  FastAPI（单端口同时提供 API 与静态页面托管）             │
│  ├─ api.py       数据接口（事件/材料/通知/热点/收件箱/任务）     │
│  └─ main.py      服务入口 + 热点榜定时刷新（断网自动降级）       │
├────────────────────────────────────────────────────────────┤
│  分析管线  pipeline/（离线可重跑，四个阶段）                    │
│  ├─ collector.py 采集器（iFinD 新闻/公告语义检索 → 去重入库）    │
│  ├─ market.py    行情采集（扶摇：日K/快照/指数）               │
│  ├─ analyze.py   clean 清洗 → extract LLM抽取 → assemble LLM  │
│  │               组装 → load 校验入库（引用回溯+权重+通知）      │
│  ├─ runner.py    增量编排（新材料导入/热点追踪共用）            │
│  └─ llm.py       可插拔 LLM 客户端（OpenAI 兼容，失败回退缓存）  │
├────────────────────────────────────────────────────────────┤
│  存储  SQLite（source_documents / events / claims /          │
│        evidence_links / event_versions / security_relations /│
│        notifications / watchlist / hot_topics / inbox_items  │
│        / document_analysis / market_snapshots / scopes）      │
├────────────────────────────────────────────────────────────┤
│  数据源  同花顺 iFinD MCP（新闻/公告/热点）· 扶摇（行情/指数）    │
└────────────────────────────────────────────────────────────┘
```

**关键设计决策**：规则与代码负责"持久化、去重、版本管理、状态约束、校验"，LLM 负责"理解文本、抽取主张、提出判断"——**模型不直接覆盖原始数据，任何结论变化都必须经过校验层**。

## 5. AI 的角色与边界

**AI 做四件事**（均有结构化输出约束与缓存兜底）：

| AI 任务 | 输入 | 输出 |
| --- | --- | --- |
| 材料结构化 | 材料标题/正文/来源/时间 | 实体、事件动作、主张、原文引用、类型（事实/观点/推测/传闻）、相关性 |
| 事件组装 | 材料摘要（含原文引用） | 核心主张归并、证据关系（支持/反驳/限定/取代）、版本链、当前结论与待确认项、标的关联 |
| 证据权重 | 主张-材料关系、材料角色 | 五维评分明细（可解释、可展开） |
| 状态判断 | 版本变化 + 状态机约束 | 状态迁移与变化原因（更新/否认/更正/过期） |

**AI 不做的事（边界）**：
- 不把传闻当事实：传闻类主张单独标注，被官方否认后标注"存在反证"，不反向改写为"已成事实"；
- 不做股价因果断言：行情仅作为"影响验证"的背景与相关性线索；
- 不生成投资建议、交易指令或收益承诺；
- 输出的每条判断必须附原文引用，引用回溯校验失败则不得作为确认依据。

## 6. 数据使用与可追溯性

- **来源**：新闻/公告/热点来自同花顺 iFinD 语义检索（返回相关段落并保留原始链接，不存储受限制的全文）；行情/指数来自扶摇（A 股日K、快照、沪深300）。
- **可追溯链路**：产品内任一主张 → 证据卡片（引用片段 + 权重明细）→ 点击"查看原文"→ 溯源抽屉展示系统保存的材料内容，**引用片段在原文中高亮定位**；同时展示披露时间与抓取时间。
- **数据性质标注**：所有材料标注 `data_origin=real`（真实采集）；界面明确区分"真实数据"与"AI 分析结论"。
- **可核验**：关键数字（事件数、材料数、引用校验通过率等）在"事件总览"顶部实时展示，全部可点开核对到原始材料。

## 8. 部署与运行

**环境要求**：Windows 10/11 + Python 3.10~3.13（若未安装 Python，安装时勾选 "Add to PATH"）。

**评审电脑运行（三步）**：
1. 拷贝整个工程文件夹到本地；
2. 双击 **`start.bat`** —— 首次运行会自动完成依赖安装（优先使用工程内置离线包 `vendor/wheels`，无需联网），随后启动服务并自动打开浏览器；
   如需单独安装依赖，也可先双击 `install.bat`。
3. 浏览器访问 **http://127.0.0.1:8000**（`start.bat` 会自动打开）。

**手动方式**：
```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
# 或（无 venv 时）
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

**联网能力说明**：产品完整功能（浏览、溯源、通知、收件箱导入）**断网可用**；联网时可"刷新热点榜 / 追踪新热点 / 采集新材料"。数据源或 LLM 不可用时系统按"缓存兜底 + 明确提示"降级，**绝不伪造实时数据**。

**⚠️ 从本仓库 clone 部署请注意：API 密钥需自行配置**

出于安全合规要求，真实密钥文件 `config/secrets.env` **不随仓库分发**（已在 `.gitignore` 中排除）。clone 后若需使用联网功能（热点榜刷新、新热点追踪、新材料采集、LLM 增量分析），请：

1. 复制 `config/secrets.example.env` 为 `config/secrets.env`；
2. 按需填入以下密钥（均可留空，留空时对应功能自动走缓存兜底降级，不影响离线浏览）：
   - `FUYAO_API_KEY` — 扶摇行情接口（[fuyao.aicubes.cn](https://fuyao.aicubes.cn) 申请）
   - `IFIND_AUTH_TOKEN` — 同花顺 iFinD MCP（[mcp.51ifind.com](https://mcp.51ifind.com) 官网"个人中心-密钥"获取）
   - `LLM_API_KEY` — OpenAI 兼容接口（如 DeepSeek，可留空）
3. **请勿将填写后的 `secrets.env` 提交到任何公开仓库**。

工程内置的数据快照与分析缓存已随仓库打包，**不配置密钥也可完整体验全部离线功能**。

## 9. 已知限制

1. **文本形态**：iFinD 新闻/公告为语义检索返回的**相关段落**（非全文），产品内保留原始链接供核验；研报观点、投资者互动类文本本期未接入专线，如需使用将按题目要求引入公开权威材料并标注来源。
2. **事件范围判定**：新事件范围由"关键词匹配 + AI 语义相关性判定"确定；同一公司不同事件的**自动跨事件归并**（例如两条单独追踪的热点实为同一事件）尚未实现，会显示为两个事件。
3. **追踪采集召回**：热点追踪依赖语义检索召回质量，可能出现"采集 N 条、AI 判定仅 1 条相关"的情况（该系统按相关性过滤，属预期行为）。
4. **标的关联兜底**：当材料未出现任何股票代码且组装未给出主体标的时，系统按代码出现频次自动兜底或转人工复核（乐鑫科技事件为人工复核补充案例）。
5. **事件发生时间**：多数材料不包含明确事件发生时间，系统保持"未知"而不以披露时间代替（这是刻意设计）。
6. **单机单用户**：无账户与权限体系，无多用户数据隔离场景。
7. **LLM 输出波动**：模型输出存在一定波动性；所有结论均经引用校验，且关键状态经人工复核（记录见 AI 验证文档）。
