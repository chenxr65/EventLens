# 测试说明（evaluation.md）

> 本文件记录 EventLens 的主链路测试、数据/接口异常测试与合规边界测试。
> 所有用例均基于**本工程内置的真实数据快照**（iFinD 新闻/公告 + 扶摇行情，采集时段 2026-09-10 ~ 2026-10-13）实际执行；
> 测试中出现的所有数字均可在产品内核对（事件总览页顶部质检栏 / 各事件详情页）。

## 0. 测试环境与方法

- 环境：Windows 11 + Python 3.13，产品本地运行（`start.bat` → `http://127.0.0.1:8000`）；
- 数据：真实采集材料 175 条（其中有效 103 / 无关 72），事件 8 个（7 个追踪中 + 1 个已停止追踪），主张 50 条，证据 87 条，版本 21 个；
- LLM：DeepSeek（OpenAI 兼容接口，可插拔）；数据源：iFinD（新闻/公告/热点）、扶摇（行情/指数）；
- 方法：对方案要求的用例逐条执行并记录结果；涉及 AI 输出的结论均以"引用回溯校验 + 人工抽查"双通道验证。

## 1. 主链路测试（T01–T12）

| 编号 | 输入情况 | 预期行为 | 实测结果 |
| --- | --- | --- | --- |
| T01 | 同一公告通过两个渠道重复导入 | 识别重复，不新增实质版本 | **通过**。收件箱导入 3 条材料：2 条入库、1 条识别为"与库内材料 #94 内容重复（哈希一致），未产生新增"；无新增版本、无新增通知 |
| T02 | 同一事件出现不同阶段材料 | 合并到同一事件，保留多来源 | **通过**。江淮事件合并 52 条材料（懂车帝测试 → 官方回应 → 媒体核查 → 第三方检测），形成 V1–V4 四个版本，证据来自 10+ 家来源 |
| T03 | 同一时间段多个不同事件 | 不因主体/主题相近而错误合并 | **通过**。8 个事件（江淮/三峡新材/科瑞思/粤万年青/兴森科技/粤芯半导体/乐鑫科技/华熙唐安）人工逐一检查，各自独立，无误合并 |
| T04 | 多家媒体转载同一传闻/公告 | 不误判为多个独立信源 | **通过**。清洗阶段完成同源聚簇：如"产销快报"7 条片段聚为 1 组、"权益变动报告书"4 条聚为 1 组；转载类材料权重降档（来源权威 0.40），并在溯源抽屉标注"同源组/重复片段" |
| T05 | 公司公告否认传闻 | 保留传闻、新增反证、更新判断 | **通过**。①粤万年青：传闻主张标注 `rumor` + `contradicted`，事件状态 `denied`，证据含两份官方澄清公告；②江淮事件：官方声明与测试方主张处于 `disputed`，冲突双方证据（supports/contradicts）并列展示，不强行给出单向结论 |
| T06 | 原始公告发布更正版 | 保留旧版，新增更正版，重算相关主张 | **部分覆盖**。语料中存在"先声明、后正式澄清公告"的两阶段材料（粤万年青），系统按两次材料分别归档并保留先后关系；但**未获得"更正版公告"真实样本**，"correction（更正）"状态与 `supersedes` 关系机制已实现（状态机与提示词支持）但本批数据未触发（如实标注，不写成已验证） |
| T07 | 材料缺失事件发生时间 | 标记未知，不填入披露时间 | **通过**。抽查全部材料：`event_time` 字段保持为空（未知），`published_at`（披露时间）独立记录；产品内四类时间分开展示，未知时间显示"未知" |
| T08 | 新材料只有格式变化/为重复转述 | 不产生实质更新通知 | **通过**。重复导入（T01）与同源聚簇材料不触发版本演化；通知仅在版本变化产生（13 条通知对应 13 次版本状态变化） |
| T09 | LLM 返回非法 JSON 或超时 | 安全失败，不覆盖当前状态 | **通过**。①结构化输出解析失败/超时统一抛 `LLMUnavailableError`，管线回退到上一次成功的预计算缓存（`backend/data/analysis/*.json`），产品可继续运行；②真实案例：首轮组装输出中 `doc_id` 混用 `10` 与 `#63` 两种格式，解析器容错处理后不产生脏数据；③实测注入"零有效材料"场景：组装阶段主动拒绝生成"空心事件"（见 ai-verification.md 案例 2） |
| T10 | 用户访问无权限材料 | 不泄露其他用户数据 | **不适用（设计说明）**。当前交付为单机单用户工程，无账户体系与多用户数据；所有数据均在本地 SQLite，无网络暴露面（服务仅监听 127.0.0.1） |
| T11 | 数据源返回空数据或限流 | 显示异常，不伪造成功结果 | **通过**。①iFinD 检索无结果时返回说明文本（非 JSON），解析器容错为空结果并如实显示"无匹配材料"（开发中真实修复）；②断网时点击"刷新热点榜"→ 明确报错"刷新失败（数据源不可用）"，榜单保留最近快照并标注批次时间；③扶摇返回业务错误码时统一抛错，不静默吞掉 |
| T12 | 模型生成不存在的原文引用 | 引用校验失败，阻止结论确认 | **通过（核心质检机制）**。首轮组装中 20 条引用有 19 条因"转述改写"被逐字校验拦截（阻断确认并触发主张降级逻辑）；修复提示词后重跑引用全部逐字可回溯，此后各批增量入库均同样通过，当前快照 **87/87 条（100%）**。产品内每条证据均展示"引用校验通过"徽标与高亮定位 |

## 2. 数据 / 接口异常测试

| 场景 | 操作 | 实测表现 |
| --- | --- | --- |
| LLM Key 无效/欠费 | 管线重跑（extract/assemble） | 抛出可识别错误 → 回退预计算缓存继续产出；产品浏览功能完全不受影响 |
| LLM Key 缺失 | 清空 `config/secrets.env` 中 LLM 配置 | `LLMClient.available=False`，管线直接走缓存路径，不发起无效请求 |
| 断网 + 刷新热点榜 | 断网下点击"立即刷新" | 前端明确提示"刷新失败：数据源不可用。榜单保留最近一次快照，不伪造实时数据" |
| 断网 + 一键追踪 | 断网下点击"追踪为事件" | 后台任务失败，任务状态 `failed` 且前端展示失败原因；不产生半成品事件 |
| 端口被占用 | 8000 端口已有进程时启动 | uvicorn 明确报 `WinError 10048`，README/说明书给出换端口指引 |
| 越权/异常参数 | 访问不存在的事件/材料 ID | 接口返回 404 与明确 detail 信息，前端错误提示 |
| 数据源限流 | 高频连续调用 | iFinD 免费版限 2 并发/秒，采集器全程串行调用；触发限流时错误可见并停止当次采集 |
| 重复执行管线 | 对同一事件范围重复运行 clean/extract/load | 幂等：clean 可重复执行；load 按范围先清后建；重复导入不产生重复版本/通知（T01/T08） |

## 3. 合规边界测试

| 合规要求 | 实现与验证 |
| --- | --- |
| 不把传闻自动认定为事实 | 传闻类主张独立类型（`rumor`）并在产品内灰显标注；被官方否认后标注"存在反证"（粤万年青案例），**不反向改写为事实** |
| 不把研报观点包装成已验证结果 | 观点类（`opinion`）独立类型与颜色；本次语料含大量媒体评论（如"三问尊界"），均标注为观点/评论而非事实 |
| 不把事件关联直接等同于股价因果 | 影响验证区固定提示："行情为影响验证的背景数据，仅呈现相关性线索，不代表因果推断或投资建议"；`impact_hypothesis` 措辞均为"可能影响…以实际为准" |
| 不生成交易指令或收益承诺 | 全产品无买卖建议功能；结论均附待确认项（如江淮事件列出 3 条待确认问题） |
| 不展示没有来源的关键数字 | 所有数字（行情快照、检测报告编号、减持数量等）均来自入库材料并附溯源；权重评分只基于入库数据计算，且标注"启发式评分，非真实性概率" |
| 不混淆真实数据与模拟数据 | 全部材料标注 `data_origin=real`；页脚与溯源抽屉明确标注"真实采集数据（iFinD）"与采集时段 |
| AI 生成内容的可追溯 | 结论区固定提示"本页结论由 AI 基于下方证据链生成并通过引用回溯校验…不构成投资建议"；首页页脚同步声明 |

## 4. 质检指标与口径说明

| 指标 | 结果 | 口径说明 |
| --- | --- | --- |
| 引用有效率 | **100%（87/87）** | 自动校验：引用片段去除空白后须在材料原文中逐字命中；失败则标记"引用未通过"并触发主张降级 |
| 错误合并率 | 0 例（人工检查） | 对 8 个事件的全部主张-证据挂接人工抽查；样本规模有限，未做大规模标注集 |
| 状态更新正确率 | 13 次版本变化，人工复核修正 1 处 | 修正案例：三峡新材事件初版状态判定与之矛盾（主张全为 supported 但事件状态 unverified），人工复核修正为 supported（记录见 ai-verification.md） |
| 通知去重率 | 无重复通知 | 重复导入与同源转述不产生通知；同一版本变化仅通知一次 |
| 相关性过滤 | 72 条无关材料被过滤 | 规则关键词 + LLM 语义二次判定（含"招股书顺带提及"类误判的语义降级，见 ai-verification.md） |

## 5. 测试结论

- 主链路（材料进入 → 事件合并 → 证据冲突 → 状态更新 → 版本回溯 → 用户通知）全流程可用且可复现；
- 引用回溯校验是本系统最高强度的质量闸门：**开发过程中它真实拦下过 19/20 条不合格引用**，修复后达到 100% 可追溯；
- 异常路径（LLM 失效、数据源不可用、重复导入、非法参数）均有明确降级或失败反馈，不存在"伪造成功"路径；
- 未覆盖项（更正公告真实样本、多用户权限、大规模标注集指标）已如实标注，见 README"已知限制"。
