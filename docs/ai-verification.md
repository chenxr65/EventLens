# AI 使用与验证记录（ai-verification.md）

> 本文件说明 EventLens 中 AI 的使用方式、可靠性机制，以及开发过程中由真实测试暴露并修复的缺陷案例。
> 原则：**不把 AI 输出当结论，只把 AI 输出当"待验证的原料"——每一条主张都必须通过引用回溯校验与状态机约束。**

## 1. AI 任务拆分与使用方式

AI（LLM）在本系统中承担四个明确任务，全部通过结构化 JSON 输出约束；模型选择为 DeepSeek（OpenAI 兼容接口），以可插拔客户端接入（`backend/pipeline/llm.py`），配置在 `config/secrets.env`：

| 任务 | 输入 | 输出（JSON Schema 约束） |
| --- | --- | --- |
| ① 材料结构化 | 单批材料（标题/正文/来源/披露时间） | 实体、事件动作、1–3 条主张、**逐字原文引用**、类型（fact/opinion/inference/rumor）、来源角色、相关性判定 |
| ② 事件组装 | 事件范围 + 全部材料摘要（含抽取阶段原文引用） | 核心主张归并（3–8 条）、证据关系（supports/contradicts/qualifies/supersedes）、版本链（状态迁移+原因）、当前结论/待确认项、标的关联 |
| ③ 权重明细 | 主张-材料关系（确定性计算） | 五维评分（R/D/I/F/Q）及角色档位（代码计算，AI 仅提供角色判定） |
| ④ 状态判断 | 版本变化 + 状态机白名单 | 状态迁移（unverified/supported/disputed/confirmed/completed/denied/corrected/stale/cancelled）与变化原因 |

**提示词关键设计**（节选）：
- 类型判定标准逐条定义（如"rumor=未经证实或已被指出不实的传闻"）；
- 引用要求："必须从材料摘要中该材料【原文引用】里**逐字选取连续一段**，不得改写、不得跨材料拼接"；
- 相关性字段 `relevant`："仅在顺带提及相关公司名、或属于无关文件时判为 false"；
- 组装阶段强制"每条主张都必须给出至少 1 条 evidences"。

**预计算 + 缓存兜底架构**：每个 LLM 阶段的输出均落盘为缓存（`backend/data/analysis/extract_*.json`、`event_*.json`）。Key 失效、超时、限流时管线自动回退缓存继续产出——**产品运行不依赖 LLM 实时可用**。

## 2. 三层可靠性机制

1. **引用回溯校验（最高闸门）**：所有证据引用在入库前做逐字校验（去空白归一化后在材料原文中必须命中）；未通过的引用标记"引用未通过"，对应主张若全部支持证据失败则自动降级为"证据不足"——**引用不实，结论不立**。
2. **冲突优先于强行总结**：官方声明与测试方主张冲突时，系统输出 `disputed` 状态并**并列展示对立证据**（如江淮事件：官方"未发生断裂" 与 测试方"三台均断裂" 同时挂接），不替用户下单向结论。
3. **低置信度安全失败**：结构化输出解析失败、材料为空、零相关材料、任务异常等场景一律**显式失败或拒绝产出**（不生成空心事件、不覆盖已有结论），失败原因对用户可见。

## 3. 真实缺陷修复案例（开发过程实测记录）

以下 5 个案例均为开发/测试过程中**真实发生**的问题，按"现象 → 根因 → 修复 → 验证证据"记录。

### 案例 1：引用"转述"被校验闸门拦截（19/20 失败 → 100% 通过）

- **现象**：首轮事件组装后，江淮事件 20 条证据引用中 19 条被引用回溯校验判定失败。
- **根因**：组装阶段提供给 LLM 的材料摘要只包含"主张文本"，未包含抽取阶段的原文引用，导致 LLM 凭记忆转述（如把"懂车帝发布封闭场地测试视频称，3台…连续全力制动中，刹车踏板支架均发生断裂"改写为"懂车帝测试称3台…全力制动中刹车踏板支架均断裂"）。
- **修复**：①摘要中为每条材料注入抽取阶段的逐字引用并明确要求"从原文引用中选取"；②保留校验闸门作为最终防线。
- **验证证据**：修复后全量重跑，**77/77 条引用逐字可回溯（100%）**；产品内每条证据显示"引用校验通过"徽标。该案例同时验证了 T12 用例的拦截机制真实有效。

### 案例 2："空心事件"——零有效材料仍生成事件

- **现象**：首次测试"热点追踪"（兴森科技业绩预告）时，采集 10 条材料但 AI 判定全部无关，系统仍生成了一个"材料摘要为空"的空洞事件。
- **根因**：组装阶段未校验"有效材料集合是否为空"；LLM 在空输入下仍按格式输出了最小事件。
- **修复**：组装阶段增加守卫——`kept`（有效材料）为空时**拒绝生成**并抛出明确错误；同时优化追踪采集的检索词策略（整条标题 → 精简关键词，新闻+公告双通道）。
- **验证证据**：修复后重跑同一热点：成功生成 5 条主张、5 条证据（100% 校验通过）、1 个版本、关联标的 002436.SZ；守卫逻辑进入 evaluation.md T09 用例。

### 案例 3：关键词相关性误判（招股书"顺带提及"）

- **现象**：关键词规则把《英特模招股说明书》《和夏科技申报稿》等文件判为与"江淮·尊界事件"相关——因为它们顺带提及"中国汽研"（事件关联方）。
- **根因**：规则匹配（关键词命中）无法区分"事件主体"与"顺带提及"。
- **修复**：抽取阶段新增 `relevant` 语义判定字段，AI 二次过滤；判定无关的材料从事件链路降级（原文保留，标注降级原因）。
- **验证证据**：首轮语义过滤降级 17 条误判材料（含上述招股书），剩余材料的每一条均可人工确认与事件直接相关。

### 案例 4：事件主体标的缺失（粤芯/乐鑫事件）

- **现象**：用户追踪的两个热点生成事件后，粤芯半导体事件缺失自身主体标的（301660.SZ），却混入一条"同日市场共同关注"的江淮汽车低相关关联；乐鑫科技事件则完全无标的。
- **根因**：组装阶段 LLM 对主体标的的提取存在遗漏/偏差（材料中代码格式不统一、标题未含代码）。
- **修复**：①**主体标的兜底机制**：入库前统计事件材料中股票代码出现频次，最高频代码未被命中且无高相关标的时，自动补充为"主体/medium"关联并标注"待人工复核"；②低相关（low）标的标签不再在事件卡片展示（详情页完整保留并附说明）；③材料无任何代码时转人工复核（乐鑫事件人工补充 688018.SH，注明补充来源）。
- **验证证据**：粤芯事件重载后自动补上 301660.SZ（标注"按材料中出现频次自动补充，待人工复核"）；乐鑫事件人工复核记录留痕于 `event_hot-37.json`。

### 案例 5：解析与展示的格式容错（两类）

- **现象 A**：组装输出中 `doc_id` 混用 `"10"` 与 `"#63"` 两种格式，整批证据一度被跳过（入库 0 条）。
- **根因**：LLM 按摘要展示格式（`#63`）复制了 ID 前缀。
- **修复**：ID 解析容错（去 `#`、去空白后转整数），无效 ID 显式跳过。
-  **现象 B**：详情页"结论结构化拆分"（已确认/仍不确定两块展示）对江淮事件失效。
- **根因**：结论中"仍不确定"多次出现导致按分隔符 split 出 3 段，前端 `===2` 判断失败。
- **修复**：改为"按首个匹配点切片"，多段落统一归入"仍不确定"区块。
- **验证证据**：重载后两条事件均正确分块展示；格式容错逻辑进入 evaluation.md T09 用例。

## 4. AI 输出的验证方法（汇总）

| 验证手段 | 覆盖对象 | 结果 |
| --- | --- | --- |
| 逐字引用回溯校验（自动） | 全部 77 条证据引用 | 100% 通过 |
| 人工抽查（开发者在产品内逐条核对） | 7 个事件的全部主张-证据挂接 | 无错误合并；1 处状态语义矛盾被人工修正（见案例 6 备注） |
| 状态机白名单校验（代码） | 全部 13 个版本的状态迁移 | 仅允许预定义状态与迁移，非法状态被拒绝 |
| 输入输出结构校验（代码） | 全部 LLM 返回（messages/JSON Schema） | 非法 JSON → 安全失败；结构缺字段 → 拒绝入库 |
| 与原始材料交叉核对（人工） | 关键数字（检测报告编号、净利润区间、减持数量等） | 均有原文出处，可在溯源抽屉定位 |

> 案例 6（备注）：三峡新材事件初版组装中，版本状态误判（主张全部 `supported` 但事件状态 `unverified`），经人工复核修正为 `supported` 并留痕。这表明系统的"引用校验"管得住证据，但"状态语义一致性"仍需人工复核兜底——已列入产品改进清单（状态机自洽性检查）。

## 5. 诚实声明

- 本产品的"AI 使用记录"来自真实开发过程，以上案例均可通过工程内文件与数据库核对（缓存文件、`load_log.md`、产品界面）；
- 未验证的事项不写入结论：如"更正（correction）"状态机制已实现但未获真实语料触发，相关表述均如实标注为"机制已实现、未获样本验证"；
- 模型自评分仅为启发式权重（非真实性概率），产品内明确标注；
- 所有 AI 判断的最终呈现均保留人工复核与用户自行核验的入口（溯源抽屉、原始链接、待确认项）。
